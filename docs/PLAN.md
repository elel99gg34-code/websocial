# 자동화 웹소설 프로그램 — 개발 계획서

> 최종 갱신: 2026-08-22 · 상태: v0.1 기초틀 구현 완료

## 1. 한 줄 정의

> **기획 한 줄만 넣으면, 설정이 무너지지 않는 연재분을 회차 단위로 계속 뽑아내는 CLI 파이프라인.**

"버튼 누르면 소설 한 편"이 아니라, **작가가 검수 가능한 중간 산출물**(기획서 → 설정집 → 회차표 → 트리트먼트 → 본문 → 검수 리포트)을
파일로 남기면서 진행하는 **반자동 연재 공장**을 목표로 한다.

## 2. 왜 이 구조인가 (핵심 문제 3가지)

장편 자동 생성이 실패하는 원인은 문장력이 아니라 아래 세 가지다. 설계 전체가 이 셋을 방어하는 데 맞춰져 있다.

| # | 실패 원인 | 증상 | 이 프로그램의 대응 |
|---|-----------|------|--------------------|
| 1 | **설정 붕괴 (Continuity drift)** | 30화쯤 주인공 눈 색이 바뀌고, 죽은 인물이 걸어다님 | `canon`(확정 사실 원장) + `characters`(상태 추적) + 회차별 다이제스트 자동 갱신 |
| 2 | **컨텍스트 폭발** | 회차가 쌓일수록 전문(全文)을 못 넣어 앞 내용을 잊음 | 전문 대신 **요약 계층**(회차 요약 → 아크 요약) + 관련 캐논만 선별 주입 |
| 3 | **평탄한 전개 (No hook)** | 매 화가 밋밋하게 끝나 이탈률 폭증 | 회차 계획에 **훅/복선(plant·payoff) 필드 강제**, 검수기가 훅 부재를 실패로 판정 |

부수 문제: **비용 통제**(회차당 단가 추적), **재현성**(모든 산출물 파일 저장 + 재개 가능), **작가 개입**(프롬프트가 코드가 아닌 `prompts/*.md`).

## 3. 범위

### v0.1 (이번 구현 — 기초틀)
- 기획 → 설정집 → 회차표 → 회차 트리트먼트 → 본문 → 규칙/AI 검수 → 퇴고 → 다이제스트(캐논 갱신) → 내보내기
- 연속성 엔진(캐논 원장, 복선 원장, 인물 상태), 컨텍스트 조립기, 프롬프트 캐싱
- **멀티 제공자**: Claude(유료·고품질) + 무료 티어(Gemini/Groq/OpenRouter/Cerebras/Mistral) + 로컬(Ollama/LM Studio)
- **단계별 모델 라우팅**: 집필은 Claude, 검수·요약은 무료 모델처럼 단계마다 다른 제공자 지정
- 비용/토큰 회계, 예산 상한, 중단/재개, mock 모드(무과금 전체 파이프라인 리허설)

### v0.2 이후 (미구현 — 로드맵)
- EPUB 내보내기, 문피아/노벨피아 등 플랫폼 업로드 자동화, 표지 생성
- 웹 대시보드, 회차별 A/B 초고 비교, 독자 반응(댓글) 피드백 루프, 임베딩 기반 캐논 검색(RAG)

### 명시적 비범위
- 타 플랫폼 작품 크롤링/학습, 저작권 침해 소지가 있는 특정 작가 문체 복제, 표절 우회

## 4. 사용자 시나리오

```bash
# 0) 준비
export ANTHROPIC_API_KEY=sk-ant-...

# 1) 프로젝트 생성 (한 줄 기획만 있으면 됨)
npm run novel -- init 회귀한-망나니 \
  --title "회귀한 망나니 도련님" \
  --genre "현대판타지" --platform "문피아" \
  --idea "재벌가 망나니가 파산 직전으로 회귀해 그룹을 재건한다"

# 2) 기획 → 설정집 → 회차표 (사람이 중간에 파일 열어 고쳐도 됨)
npm run novel -- concept  회귀한-망나니
npm run novel -- bible    회귀한-망나니
npm run novel -- outline  회귀한-망나니 --episodes 30

# 3) 연재 (1~10화 자동: 계획→집필→검수→퇴고→캐논갱신)
npm run novel -- run 회귀한-망나니 --to 10 --budget 20

# 4) 현황/내보내기
npm run novel -- status 회귀한-망나니
npm run novel -- export 회귀한-망나니 --format txt
```

무과금 리허설: 모든 명령에 `--mock`을 붙이면 API 호출 없이 동일한 파일 구조가 생성된다.

## 5. 파이프라인 (단계별 계약)

각 단계는 **입력 파일 → LLM 호출 → 검증된 출력 파일**의 순수 함수처럼 동작하며, 산출물이 이미 있으면 건너뛴다(`--force`로 재생성).

| 단계 | 명령 | 입력 | 출력 | 호출 형태 |
|------|------|------|------|-----------|
| 1 기획 | `concept` | `project.json`(아이디어) | `concept.json` (로그라인/시놉시스/주인공 결핍·목표/흥행 포인트/1화 후킹 전략) | 구조화 JSON |
| 2 설정집 | `bible` | concept | `bible.json` (세계관 규칙, 인물 카드, 용어집) | 구조화 JSON |
| 3 회차표 | `outline` | concept+bible | `outline.json` (아크 → 회차별 목표/훅/복선) | 구조화 JSON |
| 4 트리트먼트 | `write`(내부) | outline+캐논 | `episodes/ep-0001/plan.json` (비트 4~6개, 등장인물, 훅) | 구조화 JSON |
| 5 집필 | `write` | plan+컨텍스트 | `draft.md` (본문) | 산문 스트리밍 |
| 6 검수 | `qa` | draft | `qa.json` (규칙 지표 + AI 심사) | 규칙 + 구조화 JSON |
| 7 퇴고 | `revise` | draft+qa | `revised.md` → 승격된 `final.md` | 산문 스트리밍 |
| 8 다이제스트 | `write`(내부) | final | `digest.json` + 캐논/복선/인물 상태 갱신 | 구조화 JSON |
| 9 내보내기 | `export` | final × N | `exports/*.txt|md` | 없음 |

`run`은 4~8을 회차마다 반복하는 오케스트레이터다. 검수 실패 시 최대 `maxRevisions`회 퇴고하고,
그래도 실패하면 회차를 `needs_human`으로 표시하고 **멈춘다**(조용히 넘어가지 않는다).

## 6. 연속성 엔진 (이 프로그램의 핵심)

### 6.1 저장 구조 — 회차가 늘어도 컨텍스트가 선형으로 늘지 않게

```
projects/<slug>/
├── project.json         메타(장르/플랫폼/분량목표/모델설정)
├── concept.json         기획
├── bible.json           세계관·인물·용어 (거의 불변 → 프롬프트 캐시 대상)
├── outline.json         아크/회차표 + 회차 상태 머신
├── canon.json           확정 사실 원장 (회차 출처 표기)
├── foreshadow.json      복선 원장 (심음/회수 예정/회수됨)
├── characters-state.json 인물별 현재 상태(위치·관계·알고 있는 것)
├── episodes/ep-0001/    plan.json · draft.md · qa.json · final.md · digest.json
├── runs/usage.jsonl     호출별 토큰·비용 로그
└── exports/
```

### 6.2 회차 N 집필 시 주입 컨텍스트

```
[system] ── 캐시 경계 ──────────────────────────────
  1. 공통 문체 지침 (prompts/style.md)
  2. 시리즈 요약 (로그라인·장르·타깃·POV·시제)
  3. 설정집 전문 (세계관 규칙 + 인물 카드 + 용어)     ← cache_control: ephemeral
[user] ── 매 회차 달라지는 부분 ────────────────────
  4. 미회수 복선 목록 (심은 회차 표기)
  5. 관련 캐논 사실 (이번 화 등장인물·장소로 필터)
  6. 직전 3회 요약 + 직전 회차 마지막 400자
  7. 이번 회차 트리트먼트(비트/훅)
  8. 집필 지시 (분량, 금지사항, 종결 방식)
```

1~3은 시리즈 내내 바이트 단위로 동일 → 프롬프트 캐시 적중(캐시 읽기 ≈ 0.1배 단가).
4~7만 매번 새로 계산되므로 **회차가 100화가 되어도 입력 토큰이 거의 늘지 않는다.**

### 6.3 캐논 갱신 루프

집필 확정 → `digest` 호출이 (요약, 신규 확정 사실, 인물 상태 변화, 심은/회수한 복선)을 구조화 JSON으로 반환 →
원장에 회차 출처와 함께 append. 다음 회차는 이 원장을 읽는다. **쓰기는 append-only, 충돌 시 사람이 판단.**

## 7. 품질 기준 (검수기가 실제로 재는 것)

### 7.1 규칙 기반 (LLM 없이, 즉시·무료)
| 지표 | 기준(기본값) | 이유 |
|------|--------------|------|
| 공백 포함 글자수 | 목표 ±12% (기본 5,200자) | 플랫폼 회차 분량 규격 |
| 대사 비율 | 25~55% | 너무 낮으면 설명충, 높으면 시나리오 |
| 평균 문장 길이 | ≤ 45자 | 모바일 가독성 |
| 긴 문단 비율(4줄+) | ≤ 15% | 웹소설은 짧은 문단 |
| 4어절 반복구 | 3회 이상 등장 시 경고 | AI 특유의 표현 반복 |
| 종결어미 연속 | 동일 어미 4연속 시 경고 | 리듬 단조로움 |
| 금칙어 | 설정 목록 | "묘한 이질감" 류 AI 클리셰 |
| 미등록 고유명사 | 설정집에 없는 인명/지명 후보 | 설정 붕괴 조기 탐지 |
| 메타 텍스트 | "다음 화에 계속", "제N화" | 본문 오염 |

### 7.2 AI 심사 (구조화 JSON)
몰입도·캐릭터 일관성·문체·훅 강도·정보 전달을 1~5로 채점 + `issues[]` + `verdict: pass|revise` + 퇴고 지시.
**설정집/캐논과 모순되는 서술은 무조건 `revise`.**

두 결과를 합쳐 `pass | revise | needs_human`을 결정한다.

## 8. LLM 제공자 정책

### 8.1 왜 멀티 제공자인가

단계마다 요구 품질이 다르다. **본문 집필**은 한국어 장문 표현력이 결과물 그 자체이므로 최고 모델이 필요하지만,
**요약·사실 추출·형식 검사**는 구조화 JSON을 정확히 뱉기만 하면 되므로 무료 모델로 충분하다.
그래서 제공자를 하나로 고정하지 않고 **단계 → 프로필 라우팅**으로 설계했다.

```
routes: { concept: quality, bible: quality, outline: quality,
          plan: quality, draft: quality, revise: quality,
          qa: free, digest: free }
```

파이프라인 코드는 `Engine.prose()` / `Engine.json()` 만 호출하고, 제공자 차이는 어댑터가 전부 흡수한다.
새 제공자를 붙일 때 파이프라인은 건드리지 않는다.

### 8.2 지원 제공자

| 프리셋 | 종류 | 비용 | 구조화 JSON | 비고 |
|--------|------|------|-------------|------|
| `anthropic` | 공식 SDK | 유료 | 네이티브(`messages.parse`) | 한국어 장문 품질 최상, 프롬프트 캐싱 |
| `gemini` | 자체 REST | 무료 티어 | 네이티브(`responseSchema`) | 검수·다이제스트에 적합 |
| `groq` | OpenAI 호환 | 무료 티어 | `json_schema` → `json_object` 단계적 강등 | 매우 빠름 |
| `openrouter` | OpenAI 호환 | `:free` 모델 무료 | 동일 | 키 하나로 여러 공급자 |
| `cerebras` / `mistral` / `deepseek` | OpenAI 호환 | 무료 티어 / 저가 | 동일 | |
| `ollama` / `lmstudio` | OpenAI 호환 | **완전 무료(로컬)** | 동일 | 오프라인, 키 불필요 |
| `mock` | 내장 | 0 | 스키마 기반 생성 | 무과금 구조 리허설 |

OpenAI 호환 어댑터 하나가 6개 제공자를 커버한다. `baseUrl`·`model`·키 환경변수만 다르기 때문이다.

### 8.3 제공자별 구조화 출력 전략

구조화 출력이 무너지면 파이프라인 전체가 멈추므로 3단 방어를 둔다.

1. **네이티브 스키마 강제** — Anthropic `betaZodOutputFormat`, Gemini `responseSchema`, OpenAI 호환 `json_schema(strict)`
2. **지원하지 않으면 자동 강등** — `json_schema` 400 → `json_object` → 프롬프트 지시. 한 번 낮춘 모드는 세션 내내 유지
3. **검증 실패 시 1회 교정 왕복** — zod 오류 메시지를 그대로 돌려주며 다시 요청. 두 번 실패하면 중단하고 원인을 알린다

zod 스키마 하나에서 세 가지 표현(Anthropic 포맷 / OpenAI JSON Schema / Gemini OpenAPI 부분집합)을 생성한다.
Gemini는 `additionalProperties`·`minimum` 같은 키를 받지 않으므로 변환기가 걸러낸다.

### 8.4 Claude 경로 세부 (검증된 API 표면 기준)

- 기본 모델 `claude-opus-5`. `project.json` 에서 단계별로 교체 가능.
- **`temperature`/`top_p` 를 쓰지 않는다** — Opus 5 계열에서 제거된 파라미터(400 에러). 다양성은 프롬프트로 제어한다.
- `thinking: {type:"adaptive"}` + `output_config.effort` (구조 설계·집필 `high`, 다이제스트 `low`).
- 산문은 `beta.messages.stream` + `finalMessage()` — 긴 출력에서 HTTP 타임아웃 회피.
- 구조화 출력은 `beta.messages.parse` + `betaZodOutputFormat`.
- 거절 대응: `betas:["server-side-fallback-2026-07-01"]` + `fallbacks:"default"`.
  액션·범죄 소재에서 정책 거절이 나면 대체 모델이 **같은 호출 안에서** 이어받는다.
  베타 미허용 계정이면 자동으로 폴백 없이 1회 재시도하고 경고를 남긴다.
- 프롬프트 캐싱: system 마지막 블록에 `cache_control:{type:"ephemeral"}`.
- 재시도: 429/5xx/네트워크 → 지수 백오프(2s→4s→8s→16s, 최대 5회). 400/401 은 즉시 실패.

### 8.5 비용 추정

Opus 5 기준 입력 $5 / 출력 $25 per 1M, 캐시 읽기 ≈ 0.1배.

| 항목 | 입력 | 출력 | 회차당 대략 |
|------|------|------|-------------|
| 트리트먼트 | ~12K(대부분 캐시) | ~1K | $0.03 |
| 집필 | ~14K(대부분 캐시) | ~7K | $0.19 |
| 검수 | ~9K | ~1K | $0.04 |
| 다이제스트 | ~9K | ~1K | $0.03 |
| **합계(전 단계 Claude)** | | | **회차당 $0.25~0.45** |
| **합계(mixed: 검수·다이제스트 무료)** | | | **회차당 $0.18~0.30** |

→ 30화 1권 분량이 전 단계 Claude면 $8~14, mixed면 $6~9, 전 단계 무료면 $0.
단가는 `src/llm/pricing.ts` 상수이며, 등록되지 않은 모델은 비용 0으로 기록하되 "단가 미등록"으로 표시한다.
`--budget` 을 주면 상한을 넘기 직전에 다음 회차 진입을 막는다.

## 9. 아키텍처

```
src/cli.ts ─┬─ commands/*.ts   (init·concept·bible·outline·write·qa·revise·run·status·export)
            ├─ core/           types(zod) · store(파일IO) · context(컨텍스트 조립)
            │                  canon(원장) · prompt(템플릿) · config · usage · log
            ├─ llm/            client(Anthropic 래퍼·재시도·캐싱·fallback) · mock · pricing
            ├─ qa/             metrics(규칙) · check(규칙+AI 종합)
            └─ export/         exporter(txt·md)
prompts/*.md   ← 프롬프트는 코드가 아니라 데이터. 작가가 직접 튜닝.
```

기술 선택 근거:
- **TypeScript + Node 22 네이티브 타입 스트리핑** — 빌드 단계 없이 `node src/cli.ts` 실행. `tsc --noEmit`으로 타입만 검사.
- **의존성 2개**(`@anthropic-ai/sdk`, `zod`)로 제한 — 공급망 위험과 유지보수 부담 최소화.
- **파일 기반 저장소**(JSON+MD) — DB 없이 git으로 원고 이력 관리, 사람이 직접 열어 수정 가능.
- **zod 스키마 1개를 3중 사용** — 구조화 출력 스키마 + 저장 파일 검증 + TS 타입 추론.

## 11. 지금 필요한 것 (사용자 결정/제공 필요)

1. **API 키 — 최소 하나.** 셋 중 하나만 있으면 실제 생성이 된다.
   - `ANTHROPIC_API_KEY` (품질 최상, 유료) — https://console.anthropic.com/
   - 무료 티어 키 하나: `GEMINI_API_KEY` / `GROQ_API_KEY` / `OPENROUTER_API_KEY` / `CEREBRAS_API_KEY`

   - 아무것도 없으면 `--mock` 으로 구조 확인만 가능
   권장은 **Claude + 무료 키 하나(mixed 모드)** 다. 집필만 Claude로 가고 검수·요약은 무료로 빠진다.
